# مركز البنوك للألعاب — موقع المتجر الإلكتروني

مبني بـ **Next.js 14** (App Router) + **Supabase** (قاعدة بيانات، تسجيل دخول، تخزين صور).
الطلبات تُرسل مباشرة لواتساب المتجر (بدون دفع إلكتروني).

## 🚀 خطوات التشغيل (لـ Claude Code أو أي مبرمج)

### 1. تثبيت المكتبات
```bash
npm install
```

### 2. إعداد متغيرات البيئة
انسخ `.env.local.example` إلى `.env.local` وعبّي القيم:
```bash
cp .env.local.example .env.local
```

القيم المطلوبة (من إعدادات مشروع Supabase → Settings → API):
- `NEXT_PUBLIC_SUPABASE_URL` — رابط المشروع
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — المفتاح العام (publishable/anon key)

### 3. تجهيز قاعدة البيانات

**تركيب جديد بالكامل؟** شغّل ملف واحد بس داخل **Supabase → SQL Editor**:
```
supabase/schema.sql
```
هذا ينشئ كل الجداول (بما فيها نظام العروض والحملات الموسمية)، الصلاحيات (RLS)، وحساب تجريبي للإعدادات.

**عندك قاعدة بيانات شغالة أصلاً** وتريد تضيف نظام العروض بس؟ شغّل:
```
supabase/migration_offers.sql
```
هذا يضيف حقول العروض على جدول `products` وجداول `campaigns` / `campaign_products` بدون ما يمسح أي بيانات موجودة.

### 4. إنشاء أول حساب "مالك" (Owner)
1. سجّل حساب عادي من صفحة `/account` بالموقع (بريد إلكتروني + كلمة مرور)
2. بعدها بجدول `profiles` داخل Supabase، غيّر عمود `role` لهذا المستخدم من `customer` إلى `owner`
3. بهيك هذا الحساب صار عنده صلاحية كاملة للوحة الإدارة (`/admin`)

### 5. تشغيل الموقع محلياً
```bash
npm run dev
```
افتح: http://localhost:3000

### 6. النشر (اختياري لاحقاً)
```bash
npx vercel
```
واربط نفس متغيرات `.env.local` بإعدادات Vercel.

## 🔥 نظام العروض والحملات الموسمية

- **إدارة العروض** (`/admin/offers`): تشغيل/إيقاف أي عرض بضغطة، بحث وفلترة (نشطة/مجدولة/منتهية)، وتعديل حقول العرض من نفس نموذج المنتج
- **الحملات الموسمية** (`/admin/campaigns`): إنشاء حملة (رمضان، الجمعة السوداء...) مع بانر ولون ومنتجات مختارة — تظهر تلقائياً بالرئيسية أول ما يوصل تاريخها وتختفي بعد الانتهاء
- **الانتهاء التلقائي**: كل الحسابات (السعر، نسبة الخصم، العداد، الشارة) تُحسب لحظياً من التاريخ والوقت الفعلي — ما يحتاج أي عملية يدوية لما ينتهي العرض، يرجع السعر الأصلي من نفسه
- **تركيب النظام**: شغّل `supabase/migration_offers.sql` مرة وحدة بقاعدة بياناتك الحالية (Supabase → SQL Editor)

## 👥 نظام الأدوار
جدول `profiles` فيه عمود `role`:
- `customer` — زبون عادي (طلباته ومفضلته بس)
- `staff` — موظف (يدير المنتجات والطلبات، ما يوصل للإعدادات أو المستخدمين)
- `owner` — مالك (كل الصلاحيات + إدارة الموظفين + الإعدادات)

الحماية تصير على مستويين: **RLS** بقاعدة البيانات (الطبقة الحقيقية للأمان) + **middleware** بالموقع (لتجربة استخدام أفضل بس مو الحماية الوحيدة).

## 🔐 ملاحظات أمان مهمة
- المفتاح `NEXT_PUBLIC_SUPABASE_ANON_KEY` آمن للاستخدام بالواجهة الأمامية (مصمم للعرض العام)
- **لا تستخدم أبداً** `service_role key` بأي كود يوصل المتصفح — هذا فقط للسيرفر
- كل الحماية الفعلية للبيانات موجودة بـ Row Level Security داخل `schema.sql`، مو بالواجهة فقط
